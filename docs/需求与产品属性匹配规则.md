# 需求与产品属性匹配规则

实现位置：`backend/app/core/recommendation/attribute_match.py`。  
预算和品牌的硬筛选在 `backend/app/catalog/library.py`。

产品库字段来自 `electronics_products.db`。字段值为空、`未确认`、`未标注`、`不适用` 时，这一条不算命中，也不把整款产品排除。

## 怎么排序

1. 先按预算和品牌做硬筛选，筛掉的产品不参与打分。
2. 用户每选一项用途或偏好，就挂上一条或多条属性条件。同一条条件即使被多个选项同时触发，也只计 1 分。
3. 推荐度 = 命中的条件条数。条数越多越靠前。
4. 推荐度相同，发布日期越近越靠前。日期格式为 `YYYY-MM` 或 `YYYY-MM-DD`。日期不明的排在有日期的后面。
5. 仍然相同，按库内行号从小到大。
6. 取得分最高的 3 款。第 1 款是主推，后 2 款是备选。推荐依据只列出这款实际命中的条件。

自由输入里如果出现下表「也会被这些原话触发」一列中的词，和勾选对应选项的效果相同。

这些选项不产生条件，也不加分：`还不确定`、`都可以`、`不了解区别`、`不在意互联`、`都不需要`、`两类都有`，以及预算区间本身、平板「预算是否含配件」。手机的「信号和通话质量」、耳机的「佩戴舒适」「通话清晰」在库里没有对应字段，因此不加分。

## 硬筛选

| 条件 | 规则 |
| --- | --- |
| 预算区间 | 有数字的参考价必须落在选项的上下限之间。例如 4000–6000 表示参考价 ≥ 4000 且 ≤ 6000。只写了上限或只写了下限时，只卡那一端。 |
| 价格未确认 | 参考价为「未确认」的行仍保留，推荐依据里写明参考价未确认。 |
| 只要某品牌 | 原话里有「只要 / 只看 / 只买 / 只想要 / 必须 / 一定要」，或品牌一栏只填了品牌名，则只保留库里这个品牌。品牌名按库中的写法匹配，括号里的别名也算，例如「小米（Xiaomi）」能被「小米」命中。 |
| 不要某品牌 | 原话里有「不要 / 不想要 / 别推 / 别买 / 排除」并点到品牌名，则去掉该品牌。 |
| 红米 | 库里「红米」和「小米」是两个品牌。写「只要小米」不会带上红米。 |

| 经常带出门；更看重轻薄 | `weight` | 重量 ≤ 1.5kg | 轻薄 |
| 偶尔带 | `weight` | 重量 ≤ 1.8kg | |

重量写成 `kg` 时先换算成克。刷新率、容量取文本里出现的最大值。
