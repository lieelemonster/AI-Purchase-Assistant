# AI 购买助手：技术方案确认基线（联网核实版）

- 更新日期：2026-10-11。
- 依据：用户明确取消第一版人工导入产品数据库／新建知识库，并允许联网核实。
- 完整方案：[技术方案：AI 候选＋联网核实版](AI购买助手_技术方案_联网核实版.md)。
- 本文件区分已确认需求与技术建议，不代表应用已经实现。

## 1. 已确认的产品方向

- 面向 iPhone／Android 的购买选择助手。
- 品类：笔记本、手机、平板、显示器、耳机。
- 输入：选项辅助＋自由补充；未知信息保持未知。
- 正常成功结果：首选1款＋备选2款，推荐理由详细对应用户需求。
- 价格比较：三款的官方参考价格；地区、币种和具体口径仍待确认。
- 不提供购买入口、下单支付、跨店实时比价。

## 2. 最新资料来源

- 第一版不要求人工采集、整理、导入产品目录，不新建知识库。
- AI 根据已有产品知识和用户需求提出候选。
- 允许按本次推荐联网查找官方资料，核对具体型号、配置和官方参考价格。
- 商品事实应基于实际取得的证据；没有资料时保留未知或失败状态，不能将模型记忆包装成核实结果。
- 这不是后台定时爬虫、全市场资料采集或价格监控系统。

## 3. 保留的架构与建议的实现变化

**已确认继续采用：** Flutter 客户端＋Python FastAPI 后端；推荐核心与 UI／框架解耦；先在 Mac 验证接口，再接 App。

**适配新需求的技术建议：** 推荐核心调用模型、搜索和网页读取适配器；将本次证据组织成结构化内存对象，程序校验后返回。完整方案建议先验证独立搜索／网页读取接法，也允许将合格的模型内置联网工具接在同一适配边界上。具体供应商尚未选定。

产品事实不再来自预建数据库，因此 SQLite 产品表和后续 PostgreSQL 产品库迁移不再是第一版的必要路线。是否为以后新增的会话、诊断或其他功能使用持久化存储，应按实际需要另定，不自动恢复产品库。

## 4. 当前流程

选项＋自由文字 → 结构化需求 → AI 提出待核实候选 → 联网取得官方证据 → 字段／身份／价格口径核验 → AI 基于允许事实排序和解释 → 程序组装事实与引用 → Flutter 展示。

名称、配置、价格和理由中的相关事实应来自同一份本次证据对象。核验降低出错风险，不承诺模型绝不误读、官网实时完整或推荐覆盖全市场。

## 5. 明确不做

- 人工产品目录及导入后台、产品知识库、向量库。
- 账号、强历史、自训模型。
- 后台定时抓取更新价、全市场爬取、降价提醒。
- 购买链接／购买按钮、下单支付、跨店实时比价、二手购买推荐、售后及五品类以外推荐。
- Streamlit／纯 Next.js 作为最终形态。
- 本轮不实施代码、云服务购买、正式发布或应用商店上架。

选项配置、单次请求的临时证据、隔离测试样例不等于产品数据库；它们仍是实现所需结构。

## 6. 必须保留的未决项

- 查不到官方价时，保留并标缺失，还是不纳入最终推荐继续寻找。
- 官方价格地区、币种、税费、当前官网价／上市参考价口径。
- 必要信息未知、需求冲突、有效候选不足三款的行为。
- 同一型号不同配置是否可以占据多个推荐名额。
- 联网中新发现、未由AI最初提出的型号是否可加入候选。
- 会话、输入、日志和缓存的保存范围与时长。
- 模型／搜索供应商、调用预算、等待时长和部署环境。
