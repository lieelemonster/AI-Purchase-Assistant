# 购买选择助手：第一版需求说明

- 整理日期：2026-10-11
- 文档状态：第一版需求范围已确认；尚未指定的交互和数据细节单独列出。
- 变更（2026-10-11，D-09）：价格比较的口径由“官方参考价格”改为太平洋电脑网产品库的“参考价（行货价格）”，并在结果中标明来源；参数同样取自太平洋电脑网。详见 `docs/decisions.md` 和《技术方案变更：太平洋电脑网数据源》。

## 产品定位

帮助对某类产品有需求或购买意向、但自身需求模糊且不了解产品的人，做出适合自己的购买选择。

本质上解决的问题是：用户想买某类产品，却不清楚自身需求，也不了解产品差异，因此缺少判断“什么适合自己”的依据。

第一版以帮助用户做出购买选择为核心。需求梳理、产品理解和价格比较服务于这一目标。

## 一、核心功能点

| 功能点 | 第一版要求 |
| --- | --- |
| 需求表达与梳理 | 采用“自由补充＋选项辅助”：用户可以选择答案，也可以用自己的话补充和解释需求。 |
| 基于需求形成推荐 | 依据用户的选择及需求描述，优先推荐 1 款产品，并提供 2 款备选。 |
| 详细说明推荐理由 | 依据用户的选项选择与自由补充的需求描述，详细列出推荐理由，说明推荐产品与相关需求的对应关系。 |
| 候选产品价格比较 | 比较首选 1 款与备选 2 款的官方参考价格。 |

### 交互方式

第一版确定为“自由补充＋选项辅助”。

- 用户通过选项获得表达需求的帮助。
- 用户通过自由补充说明选项无法完整覆盖的需求或情况。
- 当前不规定两种方式的固定先后顺序、提问轮次或每轮问题数量。

### 推荐结果

每次推荐的目标结构为：

- **首选：** 1 款。
- **备选：** 2 款。
- **推荐理由：** 根据用户的选择和需求描述详细列出，说明产品为什么适合相关需求。
- **价格比较：** 展示这三款候选产品的官方参考价格，供用户比较。
- **购买链接：** 不提供。

本版的“自动比价”指三款候选之间的官方参考价格比较，不包含同一款产品在不同商家或平台之间的实时售价比较。

## 二、目标用户与覆盖品类

### 目标用户

对某类产品有需求或购买意向，同时存在以下困惑的人：

- 对自身需求比较模糊。
- 对这类产品及其差异不够了解。
- 希望获得帮助，做出适合自己的购买选择。

目标用户既包括想法发起者本人，也包括其他有类似困惑的人。“进入新场景”不是必要条件，不限定职业或学习阶段。

### 第一版覆盖品类

用户授权助手选择足够了解的产品品类。第一版据此覆盖：

- 笔记本电脑
- 手机
- 平板电脑
- 显示器
- 耳机

选择这些品类的依据是：能够解释常见使用需求、关键参数及取舍，并能通过公开资料核对具体型号信息。实际推荐仍需核实相关产品与价格资料，不能将对品类的了解等同于掌握所有最新型号和价格。

## 三、最核心的使用场景

### 场景描述

用户想购买某类产品，但说不清自己的具体需求，也不了解相关产品的差异。用户通过选项和自由补充表达需求，获得 1 款首选、2 款备选，以及依据自身需求详细列出的推荐理由和三款产品的官方参考价格比较，帮助自己做出购买选择。

| 场景要素 | 内容 |
| --- | --- |
| 触发时机 | 用户对某类产品有需求或购买意向。 |
| 初始状态 | 自身需求模糊，对产品了解不足。 |
| 核心困难 | 缺少判断产品是否适合自己的依据。 |
| 输入方式 | 选项选择与自由补充。 |
| 结果输出 | 首选 1 款、备选 2 款、详细推荐理由、官方参考价格比较。 |
| 期望结果 | 用户有依据地做出适合自己的购买选择。 |

### 问题来源

最初的真实案例是购买 MacBook：用户因未来办公需要购买电脑，却不清楚具体使用场景，也不了解不同型号的差异；购买后获得新信息，产生了后悔。

该案例用于说明问题，不将“学习 AI 产品经理”“预算有限”或“购买苹果电脑”推定为所有目标用户的共同条件。

## 四、「这一版先不做」

- **购买链接：** 不在推荐结果中附购买链接。
- **直接下单与支付：** 不提供交易操作。
- **商家实时售价查询与跨渠道比价：** 不比较同一产品在不同商家或平台的实时售价。
- **价格提醒：** 不提供降价或价格变化提醒。
- **二手产品购买推荐：** 首版不覆盖二手产品。
- **售后服务：** 不提供售后服务。
- **其他品类推荐：** 首版不覆盖上述五类之外的产品品类。

## 五、后续细化事项

以下属于尚未指定的细节，不写成已经确定的规则，也不自动列为“先不做”：

- 具体选项内容、问题顺序、是否追问，以及提问轮次。
- 官方参考价格的具体官方资料来源、地区、币种、对应配置及更新方式。
- 具体推荐与匹配规则。

当前文档明确产品目标、核心功能、目标用户、主要使用场景与第一版范围；未规定界面设计、技术实现或上述细化规则。
